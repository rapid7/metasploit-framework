WINAARCH64_PAYLOAD_SPACE =

The size, in bytes, of the fixed payload[] buffer declared in data/templates/src/pe/exe/template_aarch64_windows.c (SCSIZE). Shellcode longer than this would overwrite adjacent bytes in the compiled template. The AArch64 DLL uses the shared pe/dll/template.c buffers (4KiB / 256KiB) via Common::ClassMethods#set_template_default_winpe_dll, not this constant.

def inject_winaarch64_payload(code, opts, default_template)
  set_template_default(opts, default_template)

  pe = File.read(opts[:template], mode: 'rb')
  bo = find_payload_tag(pe, 'Invalid Windows AArch64 template: missing "PAYLOAD:" tag')

  if code.length > WINAARCH64_PAYLOAD_SPACE
    raise Rex::RuntimeError, "The Windows AArch64 PE generator has a max size of #{WINAARCH64_PAYLOAD_SPACE} bytes, please fix the calling module"
  end

  pe[bo, code.length] = code.dup
  pe
end

#to_winaarch64pe(framework, code, opts = {}) ⇒ String

Construct a Windows AArch64 PE executable with the given shellcode.

There is still no dedicated AArch64 service template, so this loader-style EXE is reused when a caller asked for exe-service. That is safe for psexec-style delivery: Windows still spawns the process when the SCM start request times out because the binary doesn't speak the service control protocol. DLL generation uses #to_winaarch64pe_dll instead.

def to_winaarch64pe_dll(framework, code, opts = {})
  set_template_default_winpe_dll(opts, ARCH_AARCH64, code.size)

  opts[:exe_type] = :dll

  if opts[:inject]
    raise Rex::RuntimeError, 'Template injection unsupported for AArch64 DLLs'
  else
    exe_sub_method(code, opts)
  end
end
