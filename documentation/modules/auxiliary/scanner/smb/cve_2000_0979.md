## Vulnerable Application

This module exploits CVE-2000-0979, an information disclosure vulnerability in the
share-level password authentication of Microsoft Windows 9x/Me SMB servers. The server
validates share passwords one character at a time, allowing an attacker to enumerate the
correct password byte-by-byte based on the server response. This reduces the brute-force
complexity from exponential to linear in the password length.

A zero-length password is always accepted by vulnerable servers. Each subsequent character
can then be brute-forced individually by observing the authentication response.

The module first enumerates the available shares on the target via a NetShareEnum (RAP)
request, then attempts to recover the password for each share.

Affected systems:

- Microsoft Windows 95
- Microsoft Windows 98
- Microsoft Windows 98 SE
- Microsoft Windows Me

### Setting up a test environment

1. Install Windows 9x/Me in a VM with an SMB-capable network adapter.
2. Enable File and Printer Sharing and create one or more shares using share-level
   ("share") access control, each protected with a password.
3. Ensure NetBIOS over TCP/IP is enabled so the target listens on TCP/139.

## Verification Steps

1. Start `msfconsole`.
2. `use auxiliary/scanner/smb/cve_2000_0979`
3. `set RHOSTS <target>`
4. (Optional) `set SMBName <netbios-name>` if the target's NetBIOS name is known or
   UDP/137 is blocked.
5. `run`
6. The module lists the shares and the recovered password (or `<empty>`) for each.

## Options

### SMBName

NetBIOS name of the target Win9x/Me machine, sent as the called name in the NBSS session
request. When left unset, the module discovers it with an NBNS node status query (RFC 1002,
UDP/137). Set it explicitly (e.g. `set SMBName WIN95`) when the name is already known or
UDP/137 is blocked. You can find the name from any host that can reach UDP/137 on the target
with `nmblookup -A <ip>`, `nbtscan <ip>`, or `nmap -sU -p137 --script nbstat <ip>`.

Note: a Win95 target ignores the query's source port and always replies to UDP/137. Binding
that local port requires root, so NBNS auto-discovery against Win95 must be run as root; other
Win9x/Me versions reply to the ephemeral source port and need no privileges. Auto-discovery
also does not work through a pivot, so set SMBName manually in that case.

### DELAY

Seconds to wait between password probe attempts. Defaults to `0`. Increase it to avoid
triggering rate limiting or to smooth out unstable connections.
