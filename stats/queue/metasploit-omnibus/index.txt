1b:T5a0,macOS package upgrades can leave old gem registrations behind. After a Ruby platform change, these can produce missing-extension warnings, including when the new Ruby supplies the same version as a default gem.

After installing the new payload, the installer retires obsolete non-default registrations whose gemspec and associated files still match the previous receipt. Modified and user-added registrations and all gem contents are preserved.

Verification: `ruby test/retire_package_gems_test.rb` passes all 16 tests (53 assertions). Full ARM64 and native Intel Omnibus builds pass fresh-install and controlled upgrade/reinstall checks. A real older-package upgrade also passes on ARM64 macOS 14.8.7. User-installed and modified gems, saved settings and existing PostgreSQL records survive. Intel testing ran on macOS 15.7.9; package tests used the combined dependency/PostgreSQL validation branch ([details and output](https://github.com/pauljccode/metasploit-omnibus/blob/e57d693489365002ec7f2d004be6df8cb196594a/VALIDATION.txt)).

To check the installer on a disposable Mac, upgrade an older package with `sudo installer -pkg <candidate.pkg> -target /`, then run `msfdb -h`: unchanged obsolete gems should no longer produce missing-extension warnings. Modified and user-added registrations should remain, and reinstalling the candidate should preserve the same state.

Codex assisted with implementation, tests and this description.
